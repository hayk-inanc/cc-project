# Sea Radar

Локальное веб-приложение для занятий по судовождению: карта пролива Дувр, демонстрационные суда и снимок настоящих судов из AIS по кнопке. Работает на ноутбуке преподавателя, один пользователь.

## Источники требований

- `docs/tasks/PROJECT_BRIEF.md` — задание заказчика, пользовательские истории US-01…US-10. Общие рамки проекта.
- `docs/tasks/SPRINT-*.md` — задачи backlog (B-xx), критерии приёмки и согласованные значения (форматы, поля, константы). Работаем по текущему спринту.
- `docs/tasks/*CHANGE-REQUEST*.md` — уточнения заказчика; при конфликте имеют приоритет над более ранними файлами.

Требования брать из файлов, а не из пересказа и не из памяти. Если значение есть в файле спринта — использовать его литералом, своё не придумывать. Если требования нет — спросить, а не изобретать.

## Стек

- Node.js 24, TypeScript 6.x (`strict`)
- Next.js (App Router) + React
- Leaflet 1.9.x — **только на клиенте** (обращается к `window`, ломает SSR и `next build`); CSS Leaflet подключён, у контейнера карты есть высота
- Слой OpenStreetMap Standard с атрибуцией «© OpenStreetMap contributors»
- Playwright Test — единственный раннер тестов
- Настоящие данные — AISStream (aisstream.io)

Новые зависимости без явного согласования не добавлять.

## Команды

- `npm run dev` — запуск на `http://localhost:3000`
- `npx next build` — сборка; обязательная проверка после изменений карты и клиентского кода
- `npx playwright test` — тесты

## Инварианты проекта

Действуют во всех спринтах.

**Данные**
- Одна структура судна для демонстрационных и настоящих данных; поля — по файлу спринта.
- `null` и `0` — разные вещи. Неизвестное значение показывается как «Нет данных»; скорость `0` — стоящее судно и показывается как ноль.
- Одно судно — одна запись; показывается самое свежее по времени сообщение.
- Судно без валидных координат на карте не появляется.
- Данные не искажаются: никаких «доездов», интерполяции и подстановки значений по умолчанию для настоящих судов.

**Интерфейс**
- Всегда видно, что показано: демонстрационные или настоящие данные; для настоящих — время получения, количество и оговорка, что это не все суда района.
- Ошибки (нет ключа, нет связи, ошибка источника, пустой сбор, обрыв посреди сбора) — понятной фразой, без падения приложения. «Не пришло сообщений» ≠ «судов нет».
- Название судна выводится как текст, не как HTML.
- Демонстрационная часть работает без ключа и без связи с источником.

**Район**
- Один фиксированный район (пролив Дувр); значения — в одном месте конфигурации. Запрос настоящих данных идёт по району, а не по текущему виду карты.

**Тесты**
- Суда находятся только по `data-vessel-id` / `data-icon`.
- Тесты не зависят от сети: тайлы и внешний источник в тестах заблокированы или подменены.

## Безопасность и секреты

- Приложение слушает только loopback и не открывается наружу.
- Ключ AISStream живёт только на сервере в переменной окружения из файла, исключённого из Git. Он не попадает в клиентский код, бандл, ответы API, логи, тесты, checkpoint и на экран.
- Файлы с секретами (`.env*`, ключи) не читать и не выводить; не коммитить.

## Вне рамок проекта

Не добавлять, даже «на будущее»: зоны и тревоги, историю и треки, поиск и фильтры, несколько районов, сохранение настроек, непрерывный поток в реальном времени, авторизацию и многопользовательский режим, деплой на сервер или в облако, прогнозы и «умные» функции. Внутри спринта не делать задачи следующих спринтов и не создавать заготовки под них.

## Порядок работы

- Перед правками — план без редактирования файлов.
- Одна задача backlog — небольшой шаг с явным критерием проверки.
- После задачи — показать diff и сопоставить его с заданием; отделять проверенное тестом от проверенного визуально. Решение (принять, вернуть, остановиться) принимает человек.
- Checkpoint — `docs/checkpoints/CHECKPOINT-0N.md` по шаблону `docs/checkpoints/TEMPLATE.md`, только факты, затем коммит.
